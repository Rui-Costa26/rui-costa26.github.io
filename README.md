# rui-costa26.github.io

Rui Costa's personal site: an iOS developer at Bosch Portugal who also builds his own iPhone apps (Fruidoku, Formly).
Bilingual (English at `/en/`, Portuguese at `/pt/`), fully static, hosted on GitHub Pages.

Design: concept **A2 "Tiles"**, planned by Fable (design spec and implementation plan kept outside this repo).

## Stack

- [Astro 5](https://astro.build), static output, no UI framework
- Plain CSS with tokens (`src/styles/tokens.css`), self-hosted fonts via Fontsource
- TypeScript; the only client code is the Fruidoku demo (a custom element, ~3 KB gzipped, loaded when it scrolls near), the section highlight, the copy-email button and the `/` language redirect
- Vitest for the demo engine; `scripts/check-dist.mjs` guards the build

## Develop

```sh
npm install
npm run dev        # http://localhost:4321
npm test           # demo engine: rules + every bundled level has exactly one solution
npm run build      # builds to dist/ and runs scripts/check-dist.mjs
npm run preview
```

## Where things live

| What | Where |
|---|---|
| Interface strings (EN and pt-PT, "tu" form) | `src/i18n/strings.ts` |
| Experience, skills, principles, AI block | `src/data/profile.ts` |
| Apps (home blocks and case-study pages) | `src/data/projects.ts` + images in `src/assets/<app>/` |
| Email, LinkedIn, GitHub, legal URLs | `src/data/site.ts` |
| Playable level | `src/demo/` (`levels.ts` and `FruitSprite.astro` are generated by `scripts/build-fruits.py` from the Fruidoku repo) |
| Social images | `public/og/` (generated by `scripts/build-og.py`) |

**Add an app:** add an entry to `projects` in `src/data/projects.ts` with its icon and screenshots. It gets a block on both home pages and its own `/en/<slug>/` and `/pt/<slug>/` pages. Add its social images to `scripts/build-og.py` and rerun it (the build fails if an `og:image` file is missing). The "room for the next one" tile disappears at three apps.

**Formly goes live:** set `status: 'live'` (its `category` is already `HealthApplication` for the structured data), add `{ kind: 'appstore', url: 'https://apps.apple.com/app/id…' }` to its links and its `appStoreId`.

Rules: Portuguese copy uses "tu", never "você" (the build fails if it finds "você"). AI copy stays generic: no AI product names, and never imply the apps contain AI features.

## Deploy (GitHub Pages)

1. Repository **Settings → Pages → Build and deployment → Source: GitHub Actions** (one-time).
2. Commit and push to `main` (GitHub Desktop). `.github/workflows/deploy.yml` tests, builds and deploys, then checks the legal pages still answer.

Kept from the old site: `public/app-ads.txt` (AdMob reads it from the site root, do not remove).

### The legal pages

`/fruidoku-legal/` and `/formly-legal/` are **separate repositories** (project sites) and are linked from the App Store listings. This repo must never create those paths; the build fails if it does.

## Custom domain, later

1. Add `public/CNAME` containing the domain, e.g. `ruicosta.dev`.
2. DNS at the registrar: apex `A` records `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153` (and `AAAA` `2606:50c0:8000::153`, `…8001::153`, `…8002::153`, `…8003::153`); `www` as `CNAME` → `rui-costa26.github.io`.
3. Settings → Pages → Custom domain: enter it, wait for the certificate, tick **Enforce HTTPS**. Verify the domain in your GitHub account settings (Pages → Verified domains).
4. Change `site` in `astro.config.mjs` to the new address and push. Canonical links, hreflang, sitemap and social tags follow.
5. The legal project sites move to the new domain too; the old `rui-costa26.github.io/...` links redirect, so the App Store URLs keep working. Check them after the switch.
